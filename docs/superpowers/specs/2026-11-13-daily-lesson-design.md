# 每日一课（Daily Lesson）设计

日期：2026-11-13　状态：草稿，待确认

## 为什么做

使用者目前是 N5 水平，母语中文。现有的标题讲解（`explain_items`，`scripts/fetch_news.py:505`）对每条标题都按同一个模板讲：意群切分、语法点、提示。存在三个问题：

- 讲法不随水平变化：会讲「～を押し切る」这种离 N5 很远的语法，反而每天反复出现的基础点（「の」连接名词、名词结尾省略「する」）每次都只零散地提一下。
- 每条单独讲，前后没有联系：没有「这个你学过了」，也没有「今天新学这个」。
- 只说意思，不说为什么这样写。

使用者想要的是：**每天一节课，认真读完，真正学到东西；下次再遇到时至少有印象，不会像第一次那样完全不认识。**

## 目标

1. 每天生成一节课，主角是**一个**新语法点，按固定大纲从 N5 往 N4 推进，不跳级。
2. 例句全部来自当天的真实新闻标题，讲透「为什么这样写」。
3. 记录学过的语法点和单词，并按间隔安排复习。复习时用**新的**标题作例句，而不是重复旧句子。
4. 在普通新闻列表里，标题中出现已学过的语法点时加上标记，让使用者感觉到「这个我见过」。

## 非目标

- 不改现有的新闻抓取和筛选逻辑（抓取失败重试、去重等另行处理）。
- 不替换现有的逐条标题讲解，它继续保留，作为查阅用。
- 不做账号或多用户支持，不做在线部署。仍然是本机加 `--serve`。

## 反目标（做到了也算失败的情况）

- 一节课塞进很多语法点，读不完或读完记不住。
- 课程讲解用了大量使用者还没学过的语法或术语。
- 只要某天生成失败，后面的进度就乱掉。

## 做法比较（已选 A）

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A 固定大纲 + 当天例句（已选）** | 预先排好 N5→N4 语法清单，每天取下一个未学的点，从当天标题里找例句 | 能保证循序渐进、可以复习；需要先整理大纲；当天标题里不一定有下一个点 |
| B AI 每天自选 | 告诉 Claude 已学列表，让它从当天标题里挑一个点 | 最简单，但进度跟着新闻走，容易跳级 |
| C 以词为主 | 每天精读 3 条、学 5 个词 | 积累词汇快，但解决不了「看不懂句子结构」 |

选 A 的理由：它是唯一能同时做到「每天进步一点」和「不跳级」的方案，也能直接接入现有的单词本复习。

## 设计

### 1. 语法大纲 `data/grammar_syllabus.json`

一个有序数组，约 60–80 项，覆盖 N5 和 N4 中**在新闻标题里实际会出现**的语法，再加上新闻标题特有的写法（名词结尾、「へ」表示目标、「、」代替助词、「…か」表示推测、「＝」「／」等符号）。每一项包含：

- `id`：稳定的标识，如 `no-link`、`ni-place`、`noun-end-suru`
- `level`：`N5` / `N4` / `headline`（标题特有写法）
- `title`：中文名称，如「の：把两个名词连起来」
- `brief`：一两句给 N5 学习者的说明
- `match`：用来判断一条标题是否用到这个点的规则（见第 3 节）

排列顺序就是学习顺序。**大纲草稿由 Claude 整理，在实施计划的第一步交给使用者过目，确认后才继续往下做**；之后使用者可以手动编辑这个文件，调整顺序或删减。

### 2. 学习进度 `news/progress.json`

```json
{
  "grammar": {"no-link": {"learned": "2026-11-14", "level": 1, "due": "2026-11-15"}},
  "lessons": {"2026-11-14": {"point": "no-link", "done": true}}
}
```

- 课程生成后，这个点**还不算学过**。使用者在课程页点「学完了」以后，才把它记为已学，并进入复习队列。
- 语法点的复习间隔沿用单词本的 `REVIEW_DAYS`，评分也一样分为「不认识 / 模糊 / 认识」三档。
- 单词仍然存在 `news/vocab.md`，不另建一份。
- **「学过的单词」指单词本里熟练度 ≥ 1 的词**（至少复习过一次并选了「认识」）。因为 `auto_add_vocab` 会把每天标题里的 N5/N4 词自动加进单词本（目前 118 个词里有 85 个熟练度为 0，从来没复习过），所以「在单词本里」不等于「学过」。（Claude 的决定）

### 3. 选今天的点

1. 从大纲里按顺序找第一个还没学过的点。
2. 用这个点的 `match` 规则扫描当天精选的标题。如果有 2 条以上命中，就选它。
3. 如果命中不到 2 条，沿大纲往后找，选第一个当天能命中 2 条以上的点。被跳过的点留在原位，以后有合适的标题时再学。往后最多看 10 个点，避免跳级太远；10 个以内都找不到时，当天课程改为「复习课」（见第 5 节）。
4. **等使用者（使用者已确认）**：同一时间只有一节「当前课」。最近一节课（新课或复习课都算）没点「学完了」之前，不推进新的点，也不为新的点调用 Claude；课程页继续显示这节课，但第 5 部分「复习」改用当天的标题重新找例句。这里的「前一节」指最近一节课，不是日历上的前一天，所以错过几天或某天没抓取，都不影响进度。

大纲只收录能用规则判断的点。生成课程时，Claude 只负责讲解，不推翻规则选出的例句。（Claude 的决定）

`match` 的实现交给开发者决定。建议做法：能用 janome 分词结果（词面加词性）或正则判断的，就用规则；规则判断不了的，再交给 Claude 在生成课程时确认。要求是：「学过」标记和选课**不能**每次都依赖调用 Claude。

### 4. 课程内容 `news/YYYY-MM-DD/lesson.json`

用 `claude -p` 生成，按天缓存，生成过的不再重新生成。模型用 `sonnet`（每天只调用一次，质量比速度重要；现有讲解用的是 `haiku`）。提示词里带上：今天的点、使用者已学过的语法点和单词、选出的标题。要求讲解时**只用已学过的语法和最基础的术语**。

一节课分五部分，按阅读顺序排列：

1. **今日标题**：选一条最适合的标题作主句，带注音和中文大意。
2. **逐词精读**：按原文顺序逐个词或意群讲解。每一块写明：是什么、中文意思、**为什么在这里这样用**。今天的语法点要高亮。
3. **今日语法点**：用中文讲透这个点，再拿另外 1–2 条当天标题作例句，每条都指出这个点出现在哪里。
4. **今日新词**：从这几条标题里挑 3–5 个 N5/N4 单词，优先选还没学过的（熟练度为 0 或不在单词本里）。在课程页可以直接对这些词评分，复用现有的 `/api/review` 和 `/api/vocab` 接口。课程在 `auto_add_vocab` 之后生成。（Claude 的决定）
5. **复习**：列出到期需要复习的已学语法点。每个点从当天标题里找一条新例句（用 `match` 找，找不到就只显示说明），然后让使用者选「不认识 / 模糊 / 认识」。

最后可以加一道小测验：给一条当天的新标题，问「这里的 X 是什么意思／作用」，点一下显示答案。这一项是可选的，由开发者决定做不做。

### 5. 复习课

如果当天没有合适的新点，或者到期复习的点很多（暂定超过 5 个），当天就上复习课：没有新语法点，第 1–3 部分换成到期的点，每个点配上当天的新例句。

### 6. 页面

- 新增页面 `news/lesson.html`，样式沿用 `BASE_CSS`。
- 在 `index.html` 顶部加入口，比如「今日一课」，并显示课程状态：未读 / 已学完 / 待复习 N 个。
- 课程页也可以查看历史课程，按日期列出。
- `index.html` 的标题里，已学过的语法点所在的部分加一个小标记，悬停或点击时显示「学过 · 11/14 · 点名称」。用 `match` 规则在页面生成时计算，不调用 Claude。
- 新增接口：`GET /api/lesson?date=` 读取课程和进度；`POST /api/lesson/done` 标记学完；`POST /api/grammar/review` 提交复习评分。和单词本一样，必须在 `--serve` 下才能写入。

### 7. 何时生成

`run_fetch` 在 `enrich` 之后生成当天的课程。如果失败（比如没登录 claude CLI、调用超时），只记一条日志，不影响新闻产出，课程页显示「未生成」和一个「重新生成」按钮（`POST /api/lesson/generate`）。`--page-only` 不生成课程。

### 8. 代码组织（开发者的决定）

`fetch_news.py` 已经有 1660 行。新功能放到新模块 `scripts/lesson.py`，包括选点、`match`、进度读写、生成课程和课程页模板。`fetch_news.py` 只负责调用它和挂上接口。现有代码不做重构。
