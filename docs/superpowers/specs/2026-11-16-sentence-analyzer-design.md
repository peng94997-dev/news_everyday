# 句子解析（输入框，不依赖 AI）设计

日期：2026-11-16　状态：草稿，待确认

## 为什么做

使用者是 N5 水平的中文母语者，平时会学到或自己想到一些日语句子，比如「私は映画を見ることが好きです。」，想马上看懂它的结构。现有的「句子讲解」靠 Claude 生成，会遇到登录过期、JSON 出错、要等一分钟等问题，而且只能讲新闻标题。这个功能要做到：**在一个输入框里输入任意句子，在本机用 Python 库秒出解析，完全不调用 AI 或网络服务。**

## 目标

1. 新页面 `analyze.html`，提供输入框：输入一句日语，点「解析」或按回车，就显示结果。
2. 结果包含：
   - 带注音的原句
   - 按意群切开的句子结构，每块标出作用（话题、主语、宾语、谓语、修饰等）和中文意思
   - 每个词的读音、中文意思、词性和 JLPT 等级
   - 命中的常见句型，附中文说明
   - 标出使用者学过的语法点
3. 全部在本机完成，只用已经装好的 janome、pykakasi 和项目里的 JLPT 辞书，不调用 Claude、MyMemory 或任何网络服务。
4. 每个词都可以一键加入单词本，复用现有的 `/api/vocab` 接口。

## 非目标

- 整句的中文翻译。没有 AI 或机器翻译就做不好，所以只提供逐块、逐词的意思。（Claude 的决定：MyMemory 也属于机器翻译服务，同样不用。）
- 「哪一块修饰哪一块」这种依存分析，以及长句、多层从句。这是将来的方案 B（GiNZA），这次不做。
- 新闻标题的解析：标题有省略助词、名词结尾等特殊写法，现有的逐词拆解和课程继续负责。
- 纠错，比如判断使用者自己写的句子语法对不对。

## 反目标

- 规则没把握时还硬给一个看起来很确定的错误解释。宁可显示「未识别」。
- 解析结果里出现大量 N5 学习者看不懂的术语。
- 输入框需要联网或登录才能用。

## 做法比较（已选 A）

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A janome + 规则 + 句型表（已选）** | 用现有分词结果切意群、按助词标作用，再加一张手写的常见句型表 | 不装新依赖、秒出结果，和课程、单词本共用一套词汇与语法点；看不出修饰关系，长句讲不清 |
| B 加装 GiNZA（spaCy） | 用真正的依存句法分析，再加中文说明 | 长句、从句讲得清；要多装几百 MB，启动慢，和 janome 的分词需要对齐 |

选 A 的理由：使用者是 N5，自己写和学到的句子多数比较短，A 够用，而且和现有系统一致。以后要加 B，A 的句型表和中文说明都能继续用。

## 设计

### 1. 模块 `scripts/analyze.py`

一个纯函数：输入句子和 `fetch_news.tokenize()` 的分词结果，输出解析结果。它不导入 `fetch_news`，和 `lesson.py` 的做法一样，分词结果由调用方传进来。

### 2. 切意群（文节）

- 一个意群 = 一个或多个连续的实词（名词、动词、形容词、数字、专有名词，以及前缀、后缀）+ 紧跟在后面的助词和助动词。
- 动词后面接的助动词归在同一块，比如「見ます」「見たい」「見ています」。
- **断开规则（Claude 的决定）**：如果一块以动词、形容词或助动词结尾（也就是活用词结尾、后面没有助词），而下一个词是实词，就从下一个词开始新的一块。所以「見る｜ことが｜好きです」「昨日｜見た｜映画は」都会断开。
- 句号、逗号等符号不单独成块，归到前一块的末尾。
- **多句输入（Claude 的决定）**：先按 。！？ 分成几句，每句分别解析，各自判断谓语。

### 3. 标作用（按这一块最后一个助词判断）

| 结尾 | 作用（中文） |
|---|---|
| は | 话题（说到……） |
| が | 主语；如果后面的谓语是 好き／嫌い／上手／下手／分かる／できる／ほしい 这类词，标为「对象（喜欢、会、想要的是什么）」 |
| を | 宾语（动作的对象） |
| に | 时间、地点、对象或目的地 |
| で | 地点或手段 |
| と | 和……一起；如果前一块以「」结尾，标为「引用」 |
| へ | 方向 |
| から／まで | 起点／终点 |
| の | 修饰后面的名词（……的） |
| も | 也 |
| 没有助词、以动词原形或た形结尾、后面紧跟名词块 | 修饰后面的名词（像「見る映画」「昨日見た映画」） |
| 句子最后一块（动词、形容词、名词＋です／だ） | 谓语 |
| 动词块，后面紧跟以「こと／の」开头的块 | 动作 → 名词（「こと」把前面的动作变成“……这件事”） |
| い形容词，或形容动词＋な，后面紧跟名词块 | 修饰后面的名词 |
| て／で 结尾（て形） | ……然后／……着（连接下一个动作） |
| 副词（とても、よく 等） | 修饰后面的动作或形容词 |
| 没有助词的时间名词（今日、毎日、来週 等） | 时间 |
| 以 から／ので 结尾的分句 | 原因 |
| 以 けど／が 结尾的分句 | 转折（但是） |
| 以上都不符合 | 「未识别」 |

（上面后 6 行是 Claude 的决定，补上 N5 常见的情况，避免一大半都显示「未识别」。）

**每块的中文意思（Claude 的决定）**：把这一块里实词的中文意思连起来，比如「电影」「看」；助词的作用由上面的「作用」一栏说明，不硬凑成一句译文。

### 4. 句型表 `data/sentence_patterns.json`

- 格式和语法大纲**完全相同**：`id, level, title, brief, match`，直接复用 `lesson.load_syllabus` 的校验和 `lesson.match_point` 的匹配。另外可以加一个可选字段 `syllabus`，指向语法大纲里对应的 id。如果使用者学过那个点，句型卡片上就显示「学过」。（Claude 的决定；`load_syllabus` 本来就会忽略多出来的字段。）
- 「学过的语法点」单独列一栏：显示命中且已经学过的大纲语法点，用的是 `user/progress.json` 里的记录。
- 收录约 40–60 个 N5/N4 常见句型，例如：動詞＋こと（把动作变成名词）、〜ことが好き／できる、〜たことがある、〜ています、〜てください、〜てもいい、〜てはいけない、〜たい、〜ませんか、〜ましょう、〜から／〜ので（原因）、〜けど、〜とき、〜前に／〜後で、〜ながら、〜つもり、〜ほうがいい、〜なければならない。
- 每个句型命中时，显示它的 `title`、`brief`，以及在句子里命中的片段。

### 5. 补分词的漏洞（修改 `fetch_news.tokenize`，新闻页也会受益）

- **标题专用的判断要能关掉（Claude 的决定）**：`tokenize(title, headline=True)` 新增一个参数。解析句子时传 `headline=False`，不加「结尾か＝疑似」「名词结尾省略する」「结尾へ＝即将」这类只适用于标题的提示。语法大纲里 `level` 为 `headline` 的点，也不参与句子解析的「学过」标记。否则用户输入「行きますか」，会被讲成“疑似”。

- **形式名词没有中文意思**：比如「こと」，现在是 `m: None`。加一个小字典（こと、もの、とき、ところ、の、ため、つもり、はず 等），给出中文和用法提示。
- **形容动词词干被当成普通名词**：比如「好き」。janome 的词性是 `名詞,形容動詞語幹`，**只改显示的词性**为「形容动词（な形容词）」，内部种类 `k` 仍然是 `n`，避免语法大纲里「い形容词」这个点开始误配新闻标题。（Claude 的决定）要提高 `TOKENS_VERSION`，让已有新闻重新分词。
- **解析不触发网络翻译**：`m` 为 `None` 的词，解析时不调用机器翻译，直接显示「（辞书里没有）」。

### 6. 接口与页面

- `POST /api/analyze {text}` 返回解析结果 JSON。输入限制 200 字以内，空输入返回 400。
- `analyze.html`，样式沿用 `BASE_CSS`。页面从上到下依次是：输入框、带注音的原句、意群（每块一张卡片：原文、作用、中文）、命中的句型、词表（每个词带「加入单词本」按钮）。
- 最近解析过的 10 句保存在浏览器本地（localStorage），点一下就能再看。这只是方便功能，读写失败也不影响使用。
- 新闻页、课程页、单词本的顶部导航都加一个「句子解析」入口。
- 和其他功能一样，需要 `--serve` 启动的本地服务。
